# 模組詳解

## 1. 主控制器 — `src/agent.py`

### `DeepSearchAgent` 類別

整個系統的入口與協調者。

**建構式流程**（`__init__`）：
1. 載入 `Config`（若未傳入則自動呼叫 `load_config()`）
2. 根據 `config.default_llm_provider` 初始化對應的 LLM 客戶端
3. 初始化六個處理節點（注意 `ReportStructureNode` 在 `research()` 中才建立，因其需要 `query` 參數）
4. 建立空的 `State` 物件
5. 確保輸出目錄存在

**研究流程**（`research(query, save_report=True)`）：
```python
def research(self, query, save_report=True):
    self._generate_report_structure(query)   # Step 1
    self._process_paragraphs()               # Step 2
    final_report = self._generate_final_report()  # Step 3
    if save_report:
        self._save_report(final_report)      # Step 4
    return final_report
```

**關鍵私有方法**：

| 方法 | 說明 |
|------|------|
| `_initialize_llm()` | 根據 provider 字串建立 `DeepSeekLLM` 或 `OpenAILLM` |
| `_initialize_nodes()` | 建立 `FirstSearchNode`、`ReflectionNode`、`FirstSummaryNode`、`ReflectionSummaryNode`、`ReportFormattingNode`（各傳入 `self.llm_client`） |
| `_generate_report_structure(query)` | 建立 `ReportStructureNode(llm_client, query)` 並呼叫 `mutate_state()` |
| `_initial_search_and_summary(i)` | 對第 `i` 個段落執行首次搜尋 + 首次摘要 |
| `_reflection_loop(i)` | 對第 `i` 個段落執行 `max_reflections` 輪反思 |
| `_generate_final_report()` | 收集所有段落摘要，呼叫 `ReportFormattingNode` |
| `_save_report(report)` | 產生帶時間戳的檔名，存為 `.md`，可選存 `.json` 狀態 |

### `create_agent()` 便捷函式

```python
def create_agent(config_file=None) -> DeepSearchAgent:
    config = load_config(config_file)
    return DeepSearchAgent(config)
```

## 2. LLM 層 — `src/llms/`

### `BaseLLM`（抽象基底類別）

位於 `src/llms/base.py`。

```python
class BaseLLM(ABC):
    def __init__(self, api_key: str, model_name: Optional[str] = None)

    @abstractmethod
    def invoke(self, system_prompt: str, user_prompt: str, **kwargs) -> str

    @abstractmethod
    def get_default_model(self) -> str

    def validate_response(self, response: str) -> str  # 去除前後空白
```

### `DeepSeekLLM`

位於 `src/llms/deepseek.py`。

- 使用 `openai.OpenAI` SDK，但 `base_url` 設為 `https://api.deepseek.com`
- 預設模型：`deepseek-chat`
- 預設參數：`temperature=0.7`、`max_tokens=4000`、`stream=False`
- API 金鑰優先從建構式參數取得，其次從環境變數 `DEEPSEEK_API_KEY`
- 額外方法：`get_model_info()` 回傳 provider、model、api_base 資訊

### `OpenAILLM`

位於 `src/llms/openai_llm.py`。

- 直接使用 `openai.OpenAI` SDK（預設 endpoint）
- 預設模型：`gpt-4o-mini`
- 參數與 DeepSeekLLM 相同，但不設定 `stream` 參數
- API 金鑰回退至環境變數 `OPENAI_API_KEY`

**兩者差異對照**：

| 特性 | DeepSeekLLM | OpenAILLM |
|------|------------|-----------|
| SDK | `openai.OpenAI` | `openai.OpenAI` |
| Base URL | `https://api.deepseek.com` | 預設（OpenAI 官方） |
| 預設模型 | `deepseek-chat` | `gpt-4o-mini` |
| stream 參數 | `False` | 未設定 |

## 3. 處理節點層 — `src/nodes/`

### 節點繼承體系

```
BaseNode (ABC)
├── run()              [抽象]
├── validate_input()   [可覆寫]
├── process_output()   [可覆寫]
├── log_info()
└── log_error()
    │
    ├── FirstSearchNode       ─ 回傳 dict
    ├── ReflectionNode        ─ 回傳 dict
    └── ReportFormattingNode  ─ 回傳 str (Markdown)

StateMutationNode(BaseNode)
├── mutate_state()     [抽象]
    │
    ├── ReportStructureNode    ─ 寫入段落結構至 State
    ├── FirstSummaryNode       ─ 寫入 latest_summary
    └── ReflectionSummaryNode  ─ 更新 latest_summary + 遞增 reflection_iteration
```

### `ReportStructureNode`

- **特殊之處**：建構式需要 `query` 參數（其他節點不需要）
- **`run()`**：呼叫 LLM 使用 `SYSTEM_PROMPT_REPORT_STRUCTURE`，使用者輸入即為查詢字串
- **`process_output()`**：解析 JSON Array，驗證每個物件含 `title` + `content`
- **容錯**：解析失敗時回傳兩段預設結構（「概述」+「詳細分析」）
- **`mutate_state()`**：設定 `state.query`、`state.report_title`，逐一呼叫 `state.add_paragraph()`

### `FirstSearchNode`

- **`run()`**：接收 `{title, content}` → 呼叫 LLM → 回傳 `{search_query, reasoning}`
- **容錯**：解析失敗時回傳 `{search_query: "相關主題研究", reasoning: "..."}`

### `ReflectionNode`

- 結構與 `FirstSearchNode` 幾乎相同，差異在於：
  - 使用 `SYSTEM_PROMPT_REFLECTION`
  - 輸入多了 `paragraph_latest_state` 欄位
  - 容錯預設查詢為 `"深度研究補充資訊"`

### `FirstSummaryNode`

- **`run()`**：接收 `{title, content, search_query, search_results}` → LLM 撰寫段落
- **`process_output()`**：嘗試解析 JSON 取 `paragraph_latest_state` 欄位，失敗則直接回傳清理後的文字
- **`mutate_state()`**：將摘要寫入 `state.paragraphs[i].research.latest_summary` 並更新時間戳

### `ReflectionSummaryNode`

- 與 `FirstSummaryNode` 類似，但：
  - 使用 `SYSTEM_PROMPT_REFLECTION_SUMMARY`
  - 輸入多了 `paragraph_latest_state`
  - 輸出欄位為 `updated_paragraph_latest_state`
  - `mutate_state()` 額外呼叫 `increment_reflection()`

### `ReportFormattingNode`

- **`run()`**：接收段落清單 JSON → LLM 產生 Markdown
- **`process_output()`**：移除推理文字 → 清理 Markdown 標籤 → 確保有標題
- **`format_report_manually()`**：備用方法，手動拼接 `# 標題 → ## 段落 → ## 結論`

## 4. Prompt 定義 — `src/prompts/prompts.py`

本檔定義了所有 JSON Schema 與系統提示詞。

### JSON Schema 總覽

| 名稱 | 用途 |
|------|------|
| `output_schema_report_structure` | 報告結構輸出：`[{title, content}]` |
| `input_schema_first_search` | 首次搜尋輸入：`{title, content}` |
| `output_schema_first_search` | 首次搜尋輸出：`{search_query, reasoning}` |
| `input_schema_first_summary` | 首次摘要輸入：`{title, content, search_query, search_results}` |
| `output_schema_first_summary` | 首次摘要輸出：`{paragraph_latest_state}` |
| `input_schema_reflection` | 反思輸入：`{title, content, paragraph_latest_state}` |
| `output_schema_reflection` | 反思輸出：`{search_query, reasoning}` |
| `input_schema_reflection_summary` | 反思摘要輸入：含前述所有欄位 |
| `output_schema_reflection_summary` | 反思摘要輸出：`{updated_paragraph_latest_state}` |
| `input_schema_report_formatting` | 格式化輸入：`[{title, paragraph_latest_state}]` |

### Prompt 設計要點

1. 每個 Prompt 都在 `<INPUT JSON SCHEMA>` 和 `<OUTPUT JSON SCHEMA>` 標籤中嵌入 Schema
2. 明確要求「只返回 JSON 物件，不要有解釋或額外文字」
3. 反思 Prompt 特別指示「不要刪除最新狀態中的關鍵資訊，盡量豐富它」
4. 報告格式化 Prompt 要求「如果沒有結論段落，請添加一個結論」
5. Prompt 語言為**簡體中文**（可修改為繁體中文以改善繁中輸出品質）

## 5. 狀態管理 — `src/state/state.py`

四個 `@dataclass` 類別構成巢狀結構：

### `Search`
單筆搜尋結果。欄位：`query`、`url`、`title`、`content`、`score`（可為 None）、`timestamp`。

### `Research`
一個段落的研究進度。

**關鍵方法**：
- `add_search_results(query, results)` — 批次新增搜尋結果
- `increment_reflection()` — 反思計數器 +1
- `mark_completed()` — 設定 `is_completed = True`

### `Paragraph`
報告中的一個段落。

- `title`：段落標題
- `content`：LLM 規劃的預期內容描述
- `research`：`Research` 物件，持有實際研究結果
- `is_completed()`：檢查 `research.is_completed` 且 `latest_summary` 非空

### `State`
頂層狀態容器。

**關鍵方法**：
- `add_paragraph(title, content)` → 自動設定 `order`
- `get_progress_summary()` → 回傳進度資訊字典
- `save_to_file(filepath)` / `load_from_file(filepath)` — JSON 持久化
- `mark_completed()` — 標記整個報告完成

## 6. 搜尋工具 — `src/tools/search.py`

### `SearchResult` 資料類別
與 `Search` 類別結構相似，但用於 API 層回傳值。

### `TavilySearch` 類別
封裝 `TavilyClient`：
- `search(query, max_results, include_raw_content, timeout)` → `List[SearchResult]`
- 捕獲所有例外，回傳空清單不拋出

### `tavily_search()` 便捷函式
- 若提供 `api_key`，建立臨時客戶端
- 否則使用全域單例 `_tavily_client`
- 回傳 `List[Dict]`（字典格式，與狀態物件相容）

### `test_search()` 測試函式
可直接執行 `python src/tools/search.py` 進行搜尋功能測試。

## 7. 工具函式 — `src/utils/`

### `Config` 類別（`src/utils/config.py`）

```python
@dataclass
class Config:
    # API 金鑰
    deepseek_api_key: Optional[str] = None
    openai_api_key: Optional[str] = None
    tavily_api_key: Optional[str] = None

    # 模型組態
    default_llm_provider: str = "deepseek"
    deepseek_model: str = "deepseek-chat"
    openai_model: str = "gpt-4o-mini"

    # 搜尋組態
    max_search_results: int = 3
    search_timeout: int = 240
    max_content_length: int = 20000

    # Agent 組態
    max_reflections: int = 2
    max_paragraphs: int = 5

    # 輸出組態
    output_dir: str = "reports"
    save_intermediate_states: bool = True
```

**組態載入優先順序**（`load_config()`）：
1. 指定的路徑
2. `config.py`
3. `config.env`
4. `.env`

支援兩種檔案格式：
- `.py`：使用 `importlib.util` 動態匯入
- 其他：逐行解析 `KEY=VALUE`

### 文字處理函式（`src/utils/text_processing.py`）

| 函式 | 說明 |
|------|------|
| `clean_json_tags(text)` | 移除 ` ```json ` 和 ` ``` ` 標記 |
| `clean_markdown_tags(text)` | 移除 ` ```markdown ` 和 ` ``` ` 標記 |
| `remove_reasoning_from_output(text)` | 以正則移除 LLM 輸出中的推理過程，保留 JSON |
| `extract_clean_response(text)` | 多策略提取 JSON：直接解析 → 正則找 `{...}` → 正則找 `[...]` |

| `truncate_content(content, max_length)` | 在字詞邊界處截斷文字 |
| `update_state_with_search_results(...)` | 將搜尋結果寫入狀態（工具函式） |
| `validate_json_schema(data, required_fields)` | 檢查必要欄位是否存在 |

## 8. 範例程式 — `examples/`

### `basic_usage.py`
- 載入 `config.py` 設定
- 對 "2025年人工智慧發展趨勢" 執行研究
- 顯示前 500 字報告預覽與進度摘要

### `advanced_usage.py`
- 自訂 `Config`（使用 OpenAI、增加反思次數等）
- 循環執行三個研究任務
- 每個任務儲存狀態檔
- 包含 `state_management_example()` 示範狀態保存/載入（注意：呼叫了不存在的 `Config.from_env()`，為已知 bug）

### `streamlit_app.py`
- 左側欄：API 金鑰輸入、滑桿調整參數、模型選擇
- 主區域：查詢輸入 + 預設範例
- 進度條即時顯示研究進度
- 三分頁結果展示：最終報告 / 段落詳情與搜尋歷史 / 下載按鈕
