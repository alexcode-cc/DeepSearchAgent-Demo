# 開發指南

## 如何新增 LLM 後端

### 步驟

1. 在 `src/llms/` 下建立新檔案，例如 `claude_llm.py`
2. 繼承 `BaseLLM` 並實作 `invoke()` 和 `get_default_model()`
3. 在 `src/llms/__init__.py` 中匯出
4. 在 `src/agent.py` 的 `_initialize_llm()` 中新增分支
5. 在 `Config` 中新增對應屬性

### 範例：新增 Claude 支援

```python
# src/llms/claude_llm.py
import os
from typing import Optional, Dict, Any
import anthropic
from .base import BaseLLM


class ClaudeLLM(BaseLLM):
    def __init__(self, api_key: Optional[str] = None, model_name: Optional[str] = None):
        if api_key is None:
            api_key = os.getenv("ANTHROPIC_API_KEY")
            if not api_key:
                raise ValueError("Anthropic API Key 未找到")

        super().__init__(api_key, model_name)
        self.client = anthropic.Anthropic(api_key=self.api_key)
        self.default_model = model_name or self.get_default_model()

    def get_default_model(self) -> str:
        return "claude-sonnet-4-6"

    def invoke(self, system_prompt: str, user_prompt: str, **kwargs) -> str:
        response = self.client.messages.create(
            model=self.default_model,
            max_tokens=kwargs.get("max_tokens", 4000),
            system=system_prompt,
            messages=[{"role": "user", "content": user_prompt}]
        )
        content = response.content[0].text
        return self.validate_response(content)

    def get_model_info(self) -> Dict[str, Any]:
        return {
            "provider": "Anthropic",
            "model": self.default_model,
            "api_base": "https://api.anthropic.com"
        }
```

## 如何新增處理節點

### 純輸出節點（不修改狀態）

繼承 `BaseNode`，實作 `run()` 和 `process_output()`：

```python
from src.nodes.base_node import BaseNode

class MyCustomNode(BaseNode):
    def __init__(self, llm_client):
        super().__init__(llm_client, "MyCustomNode")

    def run(self, input_data, **kwargs):
        response = self.llm_client.invoke(MY_SYSTEM_PROMPT, str(input_data))
        return self.process_output(response)

    def process_output(self, output):
        # 自訂輸出處理邏輯
        return output.strip()
```

### 狀態修改節點

繼承 `StateMutationNode`，額外實作 `mutate_state()`：

```python
from src.nodes.base_node import StateMutationNode
from src.state.state import State

class MyStatefulNode(StateMutationNode):
    def run(self, input_data, **kwargs):
        # LLM 呼叫邏輯
        pass

    def mutate_state(self, input_data, state: State, **kwargs) -> State:
        result = self.run(input_data)
        # 修改 state
        state.update_timestamp()
        return state
```

## 如何自訂 Prompt

所有 Prompt 集中在 `src/prompts/prompts.py`。

### 修改要點

1. **保持 JSON Schema 標記格式**：LLM 依據 `<OUTPUT JSON SCHEMA>` 和 `<INPUT JSON SCHEMA>` 標籤理解輸入輸出格式
2. **保持「只返回 JSON」指令**：避免 LLM 輸出額外解釋文字
3. **語言**：目前 Prompt 為簡體中文，可改為繁體中文以改善繁中報告品質
4. **溫度參數**：可在各 Node 的 `run()` 中傳入 `temperature` kwargs 覆寫預設值

### Prompt 修改為繁體中文範例

將 `SYSTEM_PROMPT_REPORT_STRUCTURE` 中的：
```
你是一位深度研究助手。给定一个查询...
```
改為：
```
你是一位深度研究助手。給定一個查詢...
```

## 如何新增搜尋引擎

### 步驟

1. 在 `src/tools/search.py` 中新增搜尋類別
2. 實作與 `TavilySearch.search()` 相同的回傳格式 `List[SearchResult]`
3. 建立對應的便捷函式
4. 在 `src/agent.py` 中依組態切換搜尋引擎

### 範例：新增 Serper 搜尋

```python
class SerperSearch:
    def __init__(self, api_key):
        self.api_key = api_key

    def search(self, query, max_results=5, **kwargs) -> List[SearchResult]:
        import requests
        resp = requests.post(
            "https://google.serper.dev/search",
            headers={"X-API-KEY": self.api_key},
            json={"q": query, "num": max_results}
        )
        data = resp.json()
        results = []
        for item in data.get("organic", []):
            results.append(SearchResult(
                title=item.get("title", ""),
                url=item.get("link", ""),
                content=item.get("snippet", ""),
                score=None
            ))
        return results
```

## 已知問題與改進建議

### 已知 Bug

1. **`advanced_usage.py` 第 99 行**：呼叫了 `Config.from_env()`，但 `Config` 類別並未定義此方法。應改為 `load_config()` 或自行建立 `Config` 並從環境變數設定金鑰。

2. **`max_paragraphs` 未實際使用**：`Config.max_paragraphs` 存在但未在任何地方限制段落數量。段落數量實際由 Prompt 控制（「最多五個段落」）。

3. **`pydantic` 和 `rich` 未實際使用**：`requirements.txt` 中列出但原始碼未 import，可考慮移除或實際整合。

### 建議改進方向

#### 短期

1. **錯誤處理強化**：目前 `research()` 中若某個段落失敗會中斷整個流程，可考慮 per-paragraph try/catch 並記錄失敗原因
2. **非同步支援**：LLM 呼叫和搜尋都是 I/O 密集操作，可使用 `asyncio` 平行處理多個段落
3. **日誌系統**：目前使用 `print()` 輸出，建議改用 `logging` 或 `rich` 的 Console
4. **Prompt 繁體中文化**：將所有 Prompt 翻譯為繁體中文

#### 中期

5. **串流輸出**：LLM 回應改為串流模式，提升使用者體驗
6. **快取機制**：對相同查詢的搜尋結果快取，減少 API 呼叫
7. **Token 用量追蹤**：記錄每次 LLM 呼叫的 token 數量與成本
8. **重試機制**：對 API 呼叫加入指數退避重試

#### 長期

9. **平行段落處理**：各段落之間互相獨立，可平行執行
10. **更多搜尋引擎**：Google Search、Bing、Serper 等
11. **引用管理**：在報告中自動加入來源引用
12. **多語言支援**：根據查詢語言自動切換 Prompt 語言
13. **品質評估**：在反思迴圈中加入品質評分，動態決定是否繼續反思
